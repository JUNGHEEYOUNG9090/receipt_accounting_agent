# Receipt Accounting Agent

영수증 이미지를 기반으로 상품 정보를 추출하고, AI를 활용해 지출 항목을 자동으로 분류하는 **AI 기반 영수증 가계부 서비스**입니다.

OCR 및 Vision 모델을 활용해 영수증 데이터를 구조화하고, 추후 LangGraph를 이용해 **검증 → 재처리 → 사용자 확인** 등의 처리 흐름을 관리하는 것을 목표로 합니다.

사용자가 최종 결과를 직접 확인하고 수정할 수 있도록 하여 OCR 및 AI 모델의 오류를 보완하는 것을 목표로 합니다.

---

## 프로젝트 소개

마트나 식자재 매장에서 장을 본 뒤 영수증을 확인하면 식품, 생활용품 등 서로 다른 종류의 상품이 하나의 영수증에 함께 포함되어 있습니다.

기존 가계부 서비스에서는 이러한 지출을 직접 분류해야 하는 경우가 많기 때문에,

> **영수증을 사진으로 찍으면 상품별로 자동 분류해주는 가계부**

를 목표로 프로젝트를 진행합니다.

현재는 다음과 같은 중분류를 기준으로 개발하고 있습니다.

```text
장바구니

├── 식비
├── 생활비
└── 기타
```

추후 실제 영수증 데이터를 확인한 후 필요에 따라 세부 분류를 추가할 예정입니다.

---

## 주요 기능

### 1. 영수증 이미지 업로드

사용자가 영수증 사진을 업로드하여 자동 분석을 시작할 수 있도록 구성합니다.

모바일 환경에서 사진을 촬영하거나 이미지를 선택할 수 있도록 반응형 UI로 개발합니다.

촬영 조건에 따라 인식 결과가 달라질 수 있기 때문에 **영수증을 세로 방향으로 촬영하는 것을 권장**합니다.

### 2. 영수증 OCR

기존에 구축한 OCR 서버를 활용하여 영수증 이미지에서 텍스트를 추출합니다.

```text
영수증 이미지
      ↓
PaddleOCR-VL v1.6
      ↓
OCR 결과
```

OCR 서버는 FastAPI와 Docker를 이용해 별도 서버로 구성했습니다.

### 3. LLM 기반 데이터 구조화

OCR 결과를 OpenAI API를 이용해 분석하여 영수증 정보를 구조화된 JSON으로 변환합니다.

```text
OCR 결과
   ↓
OpenAI
   ↓
구조화된 영수증 데이터
```

추출 항목:

- 가맹점명
- 거래일시
- 상품명
- 단가
- 수량
- 금액
- 공급가액
- 부가세
- 합계금액

### 4. Vision 기반 데이터 추출

OCR 결과의 한글 상품명 및 상품별 정보 구조화 품질을 비교하기 위해 영수증 이미지를 Vision 모델에 직접 전달하는 방식도 구현했습니다.

```text
영수증 이미지
      ↓
OpenAI Vision
      ↓
구조화된 영수증 데이터
```

OCR → LLM 방식과 동일한 영수증을 대상으로 비교하여 정확도, 처리 시간, 비용을 확인합니다.

### 5. 상품 카테고리 분류

추출된 상품을 지출 목적에 따라 분류합니다.

```text
농심)짜왕멀티 4입
→ 식비

LG)샤프란핑크옹기 3.1L
→ 생활비
```

### 6. 사용자 수정

OCR 또는 AI 모델의 결과가 항상 정확하지 않을 수 있기 때문에 최종 저장 전에 사용자가 결과를 확인하고 수정할 수 있도록 구성합니다.

예:

```text
상품명
[ CJ)스팸라이트 120g ]

금액
[ 4,950원 ]

분류
[ 식비 ▼ ]

[ 수정 완료 ]
```

### 7. 지출 내역 저장

사용자가 최종 확인한 상품 및 분류 정보를 PostgreSQL/Supabase에 저장할 예정입니다.

## 현재 처리 구조

현재는 최종 Agent Workflow를 구현하기 전에 **OCR → LLM과 Vision 방식을 비교·검증하는 단계**입니다.

```text
                영수증 이미지
                     │
            ┌────────┴────────┐
            ↓                 ↓
      PaddleOCR-VL       OpenAI Vision
            ↓                 ↓
        OCR 결과          Vision 결과
            ↓
        OpenAI LLM
            ↓
        LLM 결과
            │                 │
            └────────┬────────┘
                     ↓
                결과 비교
                     ↓
                정확도 검증
```

동일한 영수증 이미지 5장을 대상으로 다음 항목을 비교합니다.

- 상품명 인식
- 상품 개수 및 구조
- 가격 및 수량
- 공급가액 / 부가세 / 합계금액
- 처리 시간
- API 비용

## LangGraph Workflow

비교 테스트가 완료되면 실제 결과를 기준으로 LangGraph를 이용한 검증 및 후속 처리 Workflow를 구성할 예정입니다.

최종 목표 구조:

```text
START
  ↓
영수증 분석
  ↓
상품 추출
  ↓
상품 분류
  ↓
검증
  ├── 정상 ─────→ 사용자 확인
  │
  └── 문제 있음
          ↓
       재처리
          ↓
        검증
          ↓
      사용자 확인
          ↓
         저장
          ↓
         END
```

LangGraph에서는 영수증 처리 과정에서 공유되는 State와 각 처리 단계를 Node로 구성하고, 검증 결과에 따라 Conditional Edge를 이용해 다음 처리 경로를 결정하는 것을 목표로 합니다.

### 주요 개념

| 개념             | 역할                                 |
| ---------------- | ------------------------------------ |
| State            | 영수증 처리 과정에서 공유되는 데이터 |
| Node             | OCR, 추출, 분류, 검증 등의 개별 처리 |
| Edge             | 다음 처리 단계로 이동                |
| Conditional Edge | 검증 결과에 따른 분기                |
| Graph            | 전체 영수증 처리 Workflow            |

## OCR / LLM / Vision 비교

동일한 영수증을 대상으로 OCR → LLM 방식과 Vision 방식을 비교하고 있습니다.

### A. OCR 기반

```text
영수증 이미지
    ↓
PaddleOCR-VL
    ↓
OCR Text
    ↓
OpenAI LLM
    ↓
구조화 결과
```

### B. Vision 기반

```text
영수증 이미지
    ↓
OpenAI Vision
    ↓
구조화 결과
```

현재까지의 테스트에서는 Vision 방식이 상품명과 상품별 가격·수량·금액을 하나의 항목으로 구조화하는 데 상대적으로 좋은 결과를 보였습니다.

다만 영수증의 촬영 방향, 빛 반사, 접힘 등의 이미지 상태에 따라 Vision에서도 인식 오류가 발생하는 것을 확인했습니다.

- FastAPI `/ocr` API를 통해 여러 영수증 이미지 처리
- 이미지별 OCR 처리 시간 측정
- Docker 컨테이너(`receipt-ai`)로 실행
- `restart: unless-stopped` 설정
- Docker Desktop 재실행 시 OCR 서버 컨테이너 자동 실행

#### 2. OCR → LLM 처리 구현

OCR 결과를 OpenAI API에 전달하여 영수증 정보를 JSON 형태로 구조화.

추출 항목:

- 가맹점명
- 거래일시
- 상품명
- 단가
- 수량
- 금액
- 공급가액
- 부가세
- 합계금액

#### 3. OCR + LLM + Vision 비교 테스트

동일한 영수증 이미지 5장을 대상으로 OCR → LLM 방식과 Vision 방식을 비교.

```text
영수증 이미지
      │
      ├── OCR → LLM
      │
      └── Vision
```

비교 항목:

- 상품명 인식
- 상품 구조
- 가격 및 수량
- 합계 정보
- 처리 시간
- API 비용

#### 4. 테스트를 통해 확인한 내용

- OCR은 숫자와 영수증 구조를 비교적 안정적으로 추출하지만 한글 상품명에서 오인식이 발생
- OCR → LLM 방식에서는 OCR 결과의 구조적 오류가 전달되거나 상품명과 바코드/가격이 별도 상품으로 분리되는 문제가 발생
- Vision 방식에서는 이미지에서 상품명과 가격·수량·금액의 관계를 직접 파악하여 일부 테스트에서 더 안정적인 결과를 확인
- 촬영 방향과 이미지 상태에 따라 Vision 결과도 달라짐
- 동일한 영수증이라도 가로 촬영과 세로 촬영에서 인식 결과 차이가 발생

#### 5. 촬영 조건 개선

동일한 영수증을 서로 다른 방향으로 촬영하여 비교한 결과, 세로 촬영에서 상품 영역 인식이 상대적으로 안정적인 결과를 확인.

이에 따라 서비스에서 영수증 촬영 시 **세로 방향 촬영을 권장하는 안내**를 추가할 예정.

#### 6. 다음 작업

현재 5개 영수증의 OCR / LLM / Vision 결과를 비교하고 정확도를 검증하는 단계.

```text
OCR
 ↓
LLM
 ↓
Vision
 ↓
결과 비교
 ↓
정확도 검증
 ↓
LangGraph 검증 / 후속 처리 설계
```

비교 결과를 바탕으로 실제 서비스에 적합한 처리 방식을 결정하고, 이후 LangGraph 기반 검증 및 재처리 Workflow를 구현할 예정입니다.
